# 50 步 batch2 与 batch4 单因素对照报告

> 记录日期：2026-11-16 ｜ 原始实验目录：`outputs/analysis/pilot50-batch-comparison`

**batch4 已完成；相对自身训练前基线，没有观察到成功率或新增解题能力的提升。下一步选择 batch2、LR=3e-6 的单因素对照。**

| 项目 | batch2 / LR1e-6 | batch4 / LR1e-6 |
|---|---:|---:|
| 有效更新 | 50/50 | 50/50 |
| 训练前固定验证 | 42/50 | 43/50 |
| 训练后固定验证 | 42/50 | 43/50 |
| 各自新增/丢失成功题 | 0/0 | 0/0 |
| 实际优化轨迹 | 400 | 800 |
| 实际优化不同任务 | 93 | 181 |
| 生成轨迹（含补采与过滤） | 1,456 | 3,088 |
| 训练循环耗时，进度条计时 | 32分23秒 | 54分56秒 |
| 验证动作序列变化 | 9/50题 | 7/50题 |

**86% 不能算作 batch4 带来的 2 个百分点提升。** 两轮训练前使用同一最佳 SFT，但任务 1812 在 batch2 初始验证失败、batch4 初始验证成功。这一个差异在训练之前已经存在。batch4 第 50 步与本轮初始验证的成功集合完全相同。它体现了端到端执行在运行间的一题波动，具体机制没有单独定位，不能将它归因于训练收益。两轮的模型来源、固定验证名单及数据版本相同，解析配置中的学习设置变化只有任务/mini batch；critic 的 batch 随配置插值变化，但 GRPO 未启用 critic。

**更大 batch 带来了更多覆盖和更高的每条轨迹处理效率，但没有带来验证收益。** 优化轨迹翻倍，独立任务约翻倍；训练循环耗时约为原来的 1.70 倍。在这个 50 步、LR1e-6 的预算下，扩大 batch 不是已验证有效的能力改进方案。这不等于所有任务或更长训练中 batch4 都无价值，也不能排除较小或尚未跨越贪心决策边界的收益。

两轮梯度都非零且有限，平均 PPO 裁剪比例分别约 0.0076% 和 0.0091%，没有大量更新被裁剪阻断的证据。batch4 的 actor 熵前15步约0.115、后20步约0.107，没有明显塌缩；不同窗口采样任务不同，这不是固定状态的严格比较。其梯度范数均值约0.122，不能仅因为低于 batch2 的0.148就断言梯度方差已经降低。

batch4 实际优化轨迹的 Strict Reward 均值约0.598，batch2约0.568。但两轮采到并经动态过滤后使用的题不同，实际 hard 比例为62.5%和70%；这些条件采样上的训练分数不能作为固定面板准确率，也不能用来证明泛化。batch4 的原始采样成功率从早期约72.1%变为后期约66.7%，同样受任务构成影响，不能单独据此断言模型退化。

batch4 最终剩余7道失败题：16809、18581、14353、5714、12556、4764、3391。主要仍是错误购买、重复探索与规格/预算核验相关失败；4764的本次轨迹是reward_unverifiable，不应据此删除正式验证任务。相对于本轮 SFT 起点，这些失败没有被解决。

**为什么下一轮选提高学习率，而不直接延长或继续放大 batch。**

已确认同步修复路径、非零更新和正常梯度，并且 batch2/batch4 两个50步实验都没有相对自身验证基线的收益。下一项有辨别价值的假设是：新建 LoRA、LR1e-6、15步预热、50步预算的组合是否过于保守。此前权重抽检也显示更新幅度较小，但这尚不能单独证明学习率过低。将 LR 提高到3e-6，是检验该假设，而不是宣布找到最终原因。

选择回到 batch2，与已完成的 batch2/LR1e-6 作对照，可以把实际优化轨迹预算固定在400条，并降低实验成本。下一轮必须从同一最佳 SFT 重新开始；不从任一 step50 续训。保留group4、micro4、累积1、seed42、warmup15、temperature1、1:3:6采样、bypass与Strict Reward，只改变学习率。官方参数定义可参阅[veRL配置说明](https://verl.readthedocs.io/en/latest/examples/config.html)，但3e-6在本项目上的效果仍待实验。

执行命令：

```bash
bash scripts/grpo.sh --pilot-steps 50 --learning-rate 3e-6
```

入口会自动做训练前和第50步的固定50题验证、保存第50步检查点并生成含逐题增减的报告，SwanLab记录全程。新目录为 `outputs/models/grpo-stage1-v3-syncfix-pilot50-lr3e-6/`；不覆盖任何既有结果，不合并或运行固定测试。

若新实验相对自身基线出现新增成功，并且概率差异/裁剪、梯度和熵没有恶化，再判断是否值得扩展训练。若仍无新增成功，或只改变动作而不解决失败题，就停止继续只调整 batch/LR，转向固定训练题面板上的可重复收益检查和检索难度/失败技能覆盖复查。50题验证的一题就是2个百分点，需要始终对照各自初始表现，不能追逐跨运行的1题波动。

本次完成日志及逐题分析、脚本准备和干跑检查，没有启动下一轮训练或新评测。
