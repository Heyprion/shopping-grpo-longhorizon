# RL 学习信号与 30 道 SFT 错题短测面板复查报告

> 记录日期：2026-11-17 ｜ 原始实验目录：`outputs/analysis/rl-signal-review`

**初步结论：训练在正常更新，但尚未把更新转化为新增成功题。已经看到信号利用率低、候选选择不足、失败行为持续和监控口径偏窄等问题；没有看到明显的梯度爆炸、熵塌缩或 PPO 大量裁剪。**

本报告只汇总修复同步后的两轮 50 步实验：batch2/LR1e-6、batch4/LR1e-6。旧 500 步训练存在已确认的权重同步故障，不能把它与新实验混合，推断当前配方的学习趋势。检查时未发现 LR3e-6 实验的运行目录或结果，因此没有评价尚未产生的高学习率结果。

曲线见 [training_curves.png](图表/RL学习信号复查/training_curves.png)，可导出的矢量图见 [training_curves.svg](图表/RL学习信号复查/training_curves.svg)。逐步数值在 [curves.csv](../../outputs/analysis/rl-signal-review/curves.csv)，统计、来源及逐题轨迹在 [metrics.json](../../outputs/analysis/rl-signal-review/metrics.json)。图中训练曲线的粗线是过去 5 步的均值；验证只在 step0 和 step50 两个时间点执行，虚线不表示中间每一步都测过。

**一、最直接的结果：没有新增解题能力证据。**

| 项目 | batch2 | batch4 |
|---|---:|---:|
| 验证成功数，训练前→后 | 42→42 | 43→43 |
| 新增/丢失成功题 | 0/0 | 0/0 |
| 验证动作序列改变 | 9/50题 | 7/50题 |
| 实际优化轨迹 | 400 | 800 |
| 实际优化不同任务 | 93 | 181 |

batch4 的 86% 在训练前就存在。与 batch2 的 84% 差异来自任务1812在两轮初始 SFT 验证中表现不同，不能把它算成训练带来的2个百分点收益。两轮的成功题集合分别都没有改变。50题一题就是2个百分点，且当前已观察到运行间一题波动；微小的跨运行分数差异不足以证明更优配方。

日志中的训练奖励有波动，但没有清楚、可重复的持续上升证据。它统计的是当步采到、按组内奖励差异筛选的轨迹，不是固定训练面板；模型、任务构成和筛选结果都会影响它。batch4训练奖励均值0.598高于batch2的0.568，不能据此认为学到了可泛化的新能力。

**二、明显坏信号：大量采样没有形成可用梯度。**

| 项目 | batch2 | batch4 |
|---|---:|---:|
| 候选任务组 | 364 | 772 |
| 因组内同分被过滤 | 212（58.2%） | 429（55.6%） |
| 全部 reward=1 的组 | 181（49.7%） | 365（47.3%） |
| 全部 reward=0 的组 | 39（10.7%） | 80（10.4%） |
| sampling invalid 被过滤组 | 27 | 64 |
| 实际用于优化的组 | 100 | 200 |
| 生成轨迹→实际优化轨迹 | 1456→400 | 3088→800 |
| 实际优化轨迹占生成量 | 27.5% | 25.9% |

全1、全0统计与过滤原因有交集：部分全0组先因invalid被过滤，不能再将两列相加。Strict Reward仍可取部分分数，不能把它说成纯二元奖励；但实际优化中部分分数轨迹只有44/400和37/800，主要仍是0和1。

当前组内优势是 reward 减组均值，同分组没有相对学习方向，过滤是合理机制，不是一个新的梯度实现错误。[DAPO §3.2](https://arxiv.org/html/2503.14476v2#S3.SS2)也讨论了相同组奖励带来的零优势。真正的问题是，整体采样成功率接近70%，并不代表每道题都处于适合学习的中等成功概率；当前存在大量整组全对或全错，且同题轨迹可能相关。结构上的hard标签不等于模型实际的可学习难度。

还有额外的信号浪费：batch2中20个、batch4中59个已经通过筛选并被纳入当次补采缓存的组，最终因补采上限内未凑齐目标任务数，随skipped_update整次放弃；另外分别5、20个可用组因超过当次配额未被纳入。这些数量已对照生成组UID、实际优化UID及skipped_update事件核验。它是当前有界补采策略的效率代价，不能把这些接受标志都当成已训练。

后续可研究同一权重版本下保留可用组跨补采失败的缓存、按训练池实测组差异安排任务等方式。需要验证状态恢复和样本策略版本，不能仅删除过滤规则，或把不可核验奖励改成普通0分。本次没有修改这些机制，避免干扰已准备的学习率单因素实验。

**三、探索存在“文字变化多，候选变化少”的迹象，但不能把它全部当成坏行为。**

实际进入优化的每题4条轨迹中，平均有3.80/3.81种不同的首轮查询，但首个打开的商品平均只有2.01/1.85种。38/100、91/200个有效训练组的4条轨迹首先打开了同一商品。

这说明不同查询文本不等于真正探索不同候选。相同商品上的不同规格学习也可能有价值，而且“首个商品”不代表整条轨迹的全部候选；这些数字不能单独证明整体探索塌缩。结合下面的验证失败案例，可以确认候选筛选和需求核验仍是实际短板。

对batch4最终7道失败题，将已保存查询离线重放到冻结BM25索引：6题从未打开目标商品；其中5题的目标在至少一次查询的前20名。这个诊断没有运行新策略，也没有把gold信息提供给模型。前20排名不等于完整描述必然都在投影文本中可见，仍需考虑观察裁剪，但它已经说明“完全检索不到”不能解释大部分这些失败。

| 验证任务 | 保存轨迹与重放证据 | 主要复查方向 |
|---|---|---|
| 16809 电动办公桌 | 需求160×70cm；目标在首轮第3名，始终未打开，反复回到别的候选并选择140×70规格，最终循环 | 候选比较、硬规格核验 |
| 14353 三轮小吃车 | 目标曾排第3/4名，多轮改写和浏览后仍未打开，最终循环 | 搜索结果筛选、无进展检测 |
| 5714 紫色迷你制冰机 | 目标首轮第4名，选择另一个商品购买，属性和规格奖励不足 | 不应只按标题相似度决定购买 |
| 12556 双肩背包 | 目标首轮第4名，从未打开，买了另一个候选，规格分为0 | 配色、用途和商品/规格匹配 |
| 18581 户外电源 | 原需求“560万毫安左右”，查询写成560000mAh，即56万，少了一个数量级；目标不在其查询前20 | 数值、单位及需求到查询的转换 |
| 3391 婴儿推车 | 目标在查询第12/15名，从未打开，后来在旧候选间循环 | 多约束与配件齐套核验 |
| 4764 宠物头套 | 打开了目标，但终局reward_unverifiable，规格/价格不能形成可验证结果 | 单独复查规格实际生效和价格可核验性 |

最后一题不能仅凭一次无效轨迹断言整个任务或清洗结果错误。固定验证名单和成功定义保持不变；应复查轨迹、可见选项和终局证据。

**四、明显坏信号：循环、未完成和错误购买没有消失。**

下表的分母是实际进入优化的400/800条轨迹，并非部署成功率或全部生成轨迹：

| 结果 | batch2 | batch4 |
|---|---:|---:|
| wrong_purchase | 79（19.8%） | 155（19.4%） |
| repeat_loop | 34（8.5%） | 69（8.6%） |
| assistant_finished_without_environment_done | 23（5.8%） | 48（6.0%） |
| too_many_guard_rejections | 5（1.3%） | 25（3.1%） |
| max_steps | 8（2.0%） | 7（0.9%） |
| 循环、未完成、守卫耗尽、步数耗尽合计 | 17.5% | 18.6% |

因此，本轮优化仍有相当一部分信号用于“不要错误结束/不要循环/不要非法动作”等流程问题，而不是只在正确候选之间学习更精细的购物判断。batch4没有显示这些行为已经显著改善；不同任务构成也不允许将类别比例差异全部归因于batch。

**五、监控盲区：重复动作率很低，不代表循环少。**

训练日志 `trajectory/repeat_action_rate` 平均仅约0.23%/0.15%，但repeat_loop终局为8.5%/8.6%。这不是同一指标自相矛盾：`adapter/runtime.py` 的重复动作计数只比较最近3次的“工具名+参数+前置观察指纹”。隔多个查看/返回动作后重访旧商品、同义改写后回到同一候选等长周期循环，不一定计入。

建议补充诊断：跨完整轨迹的ASIN重访、搜索结果集合重叠、重复无新信息的页面往返、首次发现新候选的步骤。它们是监控指标，不直接变成长度惩罚或新增奖励，也不能机械删除所有商品重访，因为恢复规格和跨候选比较也可能合理。

**六、信用分配值得复查，但尚未确认是目标函数错误。**

batch2正优势轨迹平均约11.19步、负优势约15.43步；batch4分别约10.60、16.03步。日志中的token加权平均优势，在40/50和45/50次更新为负，整轮平均约-0.062/-0.090。

组内按轨迹减均值，并不保证按有效assistant token加权后的均值也为0；更长的失败轨迹可能对这个指标产生更大影响。这里的步骤数不是精确生成token数，因而这些数字只能提示长度与失败相关，需要逐轨迹真实token和逐回合优势统计来核验，不能据此直接宣布实现有bug。

当前同一条轨迹上的不同动作共享终局相对优势；早期合理搜索、后期错误规格、循环动作不能被直接区分。这是待复查的信用分配粗糙问题，不代表加一个长度惩罚就能解决。本项目已有token-mean和不除组std的设置，不应照搬旧GRPO的归一化问题解释本轮全部现象。

**七、目前没有看到什么。**

梯度非零且没有明显爆炸；PPO裁剪比例均值约0.0076%/0.0091%，没有大量更新被裁剪挡住的证据；熵在约0.1量级波动，未见突然塌缩。它们支持“训练没有显著数值失稳”，不能推出“配方有效”。

`actor/ppo_kl` 是actor与rollout之间的抽样诊断，不是对SFT的精确累计KL，平均值还可能因抽样出现负数，不能拿它证明所有关键token都没有失配。`actor/entropy_loss`是变化轨迹上的token均值，语法token占比很大；`actor/loss`也不是SFT交叉熵，不能要求它单调下降来证明RL有效。bypass的机制与失配边界可参考[veRL官方说明](https://verl.readthedocs.io/en/latest/algo/rollout_corr_math.html)，具体统计口径以当前固定版本代码为准。

**后续决策**

仍保留已准备好的batch2/LR3e-6、50步单因素实验，用于检验更大更新幅度能否带来相对自身基线的新增成功题；当前没有该轮结果。它不是已经证实的改进方案。不要同时更换batch、温度、配比或奖励，否则无法判断原因。

如果更高学习率依然没有新增成功，应优先做固定训练题面板复查：同一组训练题、同一执行方式、适量重复采样，对比SFT和RL检查点的平均奖励/成功概率，并核对候选探索。这样才能区分“训练题上也没学到”和“训练改善但未迁移到验证”；现有滚动采样曲线不能区分二者。再据训练池自身的失败技能和实测组差异考虑数据覆盖、教师示范或采样缓存改进，而不是继续盲目增加步数或扫学习率。

本次仅分析已有日志和轨迹、离线重放少量验证查询并生成图表。没有训练、模型合并、新策略评测、数据清洗/打标签、正式名单变更或奖励修改。
