**验证了什么**

2. 在真实发送迭代器中核对发送值，两个 rank 均逐元素完全一致。
3. 在两个真实 vLLM 副本收到权重、执行 load_weights 后，读取推理模型参数，逐元素核对接收值。
4. 对照两个 rank、两个副本的完整张量 SHA-256。初始同步及 3 次更新同步，全部抽检通过。
5. 记录推理服务的实际生成调用，确认后续采样使用了版本 1、2；第 3 次更新同步后按预算停止，没有追加采样。

**一并修复了 Ray 预算路径传递。**

veRL 在将 runtime_env 交给 Ray 时使用未解析的 OmegaConf 转换，原 YAML 的 `${oc.env:SHOPPING_TASK_BUDGETS,''}` 被原样放进 worker 环境。第一次启动检查发现后，在任何有效更新之前停止。`scripts/train_grpo.py` 现显式传递预算文件的具体字符串路径，增加了模拟未解析转换的回归断言。第二次真实运行的 Ray 配置已记录规范预算路径。没有改动预算文件、数据名单、奖励或学习配方。

**bypass mode 的判断：当前保留，监测训练与推理概率差异。**

当前配置为 `bypass_mode=true`、`loss_type=ppo_clip`、`rollout_is=null`、`rollout_rs=null`。安装代码把 `old_log_probs` 指向实际采样记录的 `rollout_log_probs`，因此 PPO 比率是：

```text
ratio = exp(actor_log_prob - rollout_log_prob)
```

它节省旧策略 log-prob 的单独重算，仍使用 actor 前向、反向传播与 clip=0.2。PPO 比率已经包含相对行为策略的概率比，不能简单再乘一层重要性权重。与 [veRL 官方 bypass 说明](https://verl.readthedocs.io/en/latest/algo/rollout_corr.html) 和[数学说明](https://verl.readthedocs.io/en/latest/algo/rollout_corr_math.html)一致；具体行为以当前固定 0.8 安装代码为准。

稳定性风险来自 actor 与 rollout 的失配：BF16 合并舍入、FSDP 与 vLLM 的算子差异、错误或陈旧的同步、以及不一致的采样概率定义。失配过大时，策略比率在参数更新前就可能偏离 1，导致不必要裁剪、噪声和偏差。当前 temperature=1/top_p=1/top_k=-1，有助于避免截断采样分布带来的额外不一致；当前训练循环是收集一批、更新、同步后再采样，rollout 的 async 模式不等于持续使用陈旧权重的全异步训练。

| 1 | 0.000391 | 0 | 0.149 |
| 2 | 0.000244 | 0 | 0.247 |

本次没有看到大量提前裁剪或梯度异常。但该 KL 是日志中的平均抽样估计，不能保证所有关键决策 token 的概率比都正常；这 3 步还在 warmup，不能证明常态学习率或长期训练稳定。

关闭 bypass 并不自动消除推理失配。切到 decoupled 模式，需要合理处理 rollout、重算旧策略和当前策略三者的差异；只关闭开关而不配套校正，可能只是把失配隐藏起来。目前仓库动态采样的预检和训练循环均显式要求 bypass=true，直接改为 false 会被拒绝。这个限制来自当前实现，不是 GRPO 的理论要求。

**下一步配方建议**

先从原最佳 SFT 开始，保留修复后的配置 C，做约 50 次有效更新的学习验证，重新记录同一执行方式下的训练前及第 50 步固定 50 题验证。保持 group4、LR=1e-6、warmup15、温度1、1:3:6 采样及 bypass；本次仅证明闭环通了，没有测出更优配方。

同时添加被动概率差异统计：更新前的 actor−rollout log-prob 差、比率分位数/尾部、裁剪比例、有效样本量，并分开查看查询、候选和规格等关键决策位置。尽量复用 actor 更新已有的前向结果，避免每步额外重算整个长轨迹。不要只看平均 KL 或全 token 平均熵。

如果闭环正常且没有严重概率失配，但验证/训练改善仍不稳定，优先单独比较有效任务 batch2→4：group4 和每卡 micro4 保持，令全局 batch 从 8→16 条轨迹、累积从 1→2，减少每次更新只依赖两道任务的方差。保持学习率不变以便解释。

如果真实策略在训练题上仍几乎不移动，再单独比较 LR=1e-6 与 3e-6。只有观察到持续的比率异常或大量裁剪，再决定引入拒绝采样或支持 decoupled 校正；不要同时更改 bypass、学习率、batch、温度和难度分布。所有决策依据训练及正式验证，固定测试不参与配方选择。
