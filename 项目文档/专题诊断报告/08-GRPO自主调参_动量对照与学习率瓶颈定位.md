# GRPO 自主调参、Adam 动量反事实对照与学习率瓶颈定位报告

> 记录日期：2026-11-18 ｜ 原始实验目录：`outputs/analysis/rl-autonomous-run`

**结论：修复同步后的短实验中，最有证据支持的瓶颈是LoRA有效更新幅度过小。固定Adam beta1=0，将LR从3e-6提高到3e-5后，固定30题短测从2/30提升到7/30，新增5题、丢失0题。已找到一个有实测提升的候选配方。**

四轮均从同一最佳SFT起点新建LoRA，batch2、group4、micro4、累积1、warmup15、500步调度器、50次有效更新；每轮实际优化400条轨迹。未跑完整200题测试。普通采样的原1000题、1:3:6候选频率、seed42、Strict Reward及bypass均不变。

| 配方 | 本轮SFT起点→RL，成功题/30 | 新增/丢失 |
|---|---:|---:|
| LR3e-6，beta1=0.9，普通采样 | 2→3 | 2/1 |
| LR3e-6，beta1=0.9，focus16 | 2→2 | 1/1 |
| LR3e-6，beta1=0，普通采样 | 1→1 | 0/0 |
| LR3e-5，beta1=0，普通采样 | 2→7 | 5/0 |

**为什么现在把更新幅度列为主要瓶颈。**

在beta1=0的两轮之间，已核对实际resolved_config：data、algorithm、任务采样、动态补采和actor其余设置相同，优化器唯一变化是LR 3e-6→3e-5。低LR成功集合完全未变，高LR新增5道完整Strict成功且没有丢失原本成功题，平均Strict Reward从0.13127升至0.28056。新增题号为38、164、893、1140、1434，逐题动作及终局证据保存在 `gained_cases.json`。

此前三步测量显示，单步优势加权log-prob增量只有约1e-5～1e-4量级；三处LoRA权重检查也显示低LR更新很保守。原1000题普通采样的50步约只优化95道不同任务，大部分任务只更新一次。增加重复训练虽然提高了采样利用率，却仍未带来成功率净提升，因此不能把数据覆盖或重复次数单独当成已确认的主因。

**动量是局部问题，单独修改不足以提高成绩。**

先做3次正常更新测量，有2次当前批次PPO目标反而变差。随后用相同LoRA参数、Adam状态、调度器、Torch RNG及完全相同轨迹做控制对照，仅改变beta1；每批对照后恢复正常分支的完整状态，不改源检查点。结果如下，正数表示loss下降：

| 实际更新编号 | 正常beta1=0.9 | beta1=0 |
|---|---:|---:|
| 51 | 0.00001260 | 0.00002328 |
| 52 | -0.00013210 | 0.00007141 |
| 53 | 0.00008380 | 0.00036624 |

beta1=0在3/3批次上局部改善更好，正常动量在其中1次逆当前目标。但beta1=0、LR3e-6的完整50步仍是1→1/30，故不能宣称动量是整体无收益的唯一原因，或单独去动量已解决问题。高LR下beta1=0.9尚未对照，不能断言beta1=0是提升的必要条件。

**固定训练题复查与实现检查。**

16道固定训练来源题，每题T=1采样4次：SFT 43/64，普通LR3e-6模型35/64，focus16模型41/64；平均Strict Reward分别0.71875、0.603125、0.705729。这些小面板没有支持前两种配方已改善训练能力。没有把这些有限采样差异写成整个训练池的精确退化。

LoRA参数确实更新；三处抽检底座权重与SFT逐元素相同，没有发现合并恢复后残留漂移。真实双卡小模型验证了诊断快照对参数、Adam状态、调度器和预测的精确恢复。控制脚本只在显式探针下安装，不改变正式训练恢复方式。相关CPU检查已通过：pipeline21项、任务采样16项、对齐探针2项。

原500步训练另有已确认并修复的LoRA同步故障，导致rollout未跟随actor。这是原先长跑失效的独立原因；本报告的更新幅度结论仅用于修复同步后的短实验。

固定面板首次因并发76条超出64环境槽而失败，改为每批8题后通过；同批动量对照首次因诊断快照FSDP分片状态切换而失败，修复后先通过真实双卡恢复自检，再完成对照。两次失败不计入任何准确率结果。

**结论的范围。**

30题来自历史SFT测试失败，历史结果为0/30；当前原生推理起点在各轮为1～2/30，因此只按各轮实际起点计收益。本轮提升是这个诊断子集上的16.7个百分点，不是完整200题测试的总体提升。尚未做独立重复、高LR标准动量对照、原50题验证集能力保留和长期训练稳定性评估；不直接承诺500步继续上涨。

**下一步已具备的可执行配方。**

```bash
bash scripts/grpo.sh --pilot-steps 50 --learning-rate 3e-5 --adam-beta1 0   --output outputs/models/grpo-pilot50-lr3e5-beta0-repeat
```

开机后优先独立复跑这组50步，确认可重复性，再用原50题验证集检查是否损失原本能力；确认后才扩展训练步数。每批继续2题，不再做batch4；保持原训练源和Strict Reward，不使用focus16，不重采30题名单。上述命令包含自动30题前后评测、step50保存及SwanLab记录。

按用户“找到较稳定原因即关机”的规则，本轮到此结束，不再追加GPU实验。完整配置、逐题、逐批证据见 `results.json`、`gained_cases.json`、各模型的 `validation_report.json` 及既有SwanLab项目。关机请求结果另存 `shutdown_request.json`。
