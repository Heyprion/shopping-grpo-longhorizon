- `labels.jsonl`：每题的品类、复杂度、子项得分、原始来源和指令重复组。
- `pools/`：固定候选池，互不重叠，重复指令组不跨池。
- `reserves/`：各池尚未入选的题，顺序固定；训练扩量只取本阶段训练池。
- `registry.jsonl`：每题所属池、顺序、是否已入选、入选批次。`selected` 不等于已经训练；本次 `execution_status` 均为 `not_started`。
- `manifest.json`：所有首批名单路径、数量、类别/难度/联合分布、校验和、后续追加批次。
- `rounds/`：实际补题后才产生；首批名单及验证/测试名单保持原样。

首批 SFT 题目在 `data/sft/train_tasks.jsonl` / `validation_tasks.jsonl`，示范采集后才能训练。RL 题目在 `data/grpo/` 的 JSONL / Parquet；测试在 `data/evaluation/tasks.jsonl`。完整 eval 候选池及 3 条跨来源重复任务均受防泄漏资源保护。

```bash
# 核验已经固定的全部文件，不重新抽题。
PYTHONPATH=src .venv/bin/python scripts/prepare_data_splits.py verify

# 预览再补 1,000 道 RL 新题，不改任何登记。
PYTHONPATH=src .venv/bin/python scripts/prepare_data_splits.py extend --stage rl --count 1000 --dry-run

# 明确要求补题时去掉 --dry-run；新批次保存为 rounds/rl_001.jsonl 与 .parquet。
# 改配比可增加 --ratios 10 50 40；SFT 补题使用 --stage sft。
```

后续追加的题不得与之前任何已入选批次重叠。配额超出剩余库存时会报错，不会从验证或测试池补数。补题不自动启动训练。
